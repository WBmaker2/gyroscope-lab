# 손 점검 기록 (자동 검사로 못 하는 것들)

작성일: 2026-09-23. 실제 브라우저(Playwright + Chrome 헤드리스)로 직접 확인했다.
‘통과’는 흉내·측정 결과이며, 사람과 함께 써보는 검사는 마지막에 따로 적었다.

## 1. 읽기 순서 — 통과

见出し 순서: H1(질문) → H2 예측 → H2 실험 → H3 팽이 관찰·수치표·시간 그래프·조건 설정 →
H2 비교 → H3 실행 A·B → H2 기록. 대화상자见出し는 닫혀 있을 때 트리에 안 나온다.
DOM 순서와 눈 순서가 같다. 건너뛰기 링크가 맨 앞에 있다.

## 2. 고대비 모드 — 통과(대응 코드 추가)

`forced-colors: active`에서 확인했다.

- 버튼·입력·카드·그림 테두리가 시스템 색으로 보인다.
- 주요 버튼은 시스템 버튼색 + 2px 테두리로 보인다. 반짝임은 꺼진다.
- 키보드 포커스는 3px 시스템 강조 테두리다.
- 그래프 선은 실선/파선 + 글자 범례라 색이 바뀌어도 구분된다.

## 3. 200% 확대 — 통과

1440px에서 200% 확대(유효 720px)로 확인했다. 가로 넘침 0, 상태 표시·버튼 다 보인다.
320px 실측에서도 넘침 0이다.

## 4. 과제 문장 — 쉽게 고침

- “옆(옆 방향)으로 돌아가며 세차한다” → “옆으로 돌면서 세차한다” (겹말 제거).
- “너테이션이 보여도 실패가 아닙니다” → “축이 떨리면서 돌아도(너테이션) 실패가 아닙니다” (낱말 풀이).

## 5. 사람과 함께 써보기 — 아직 못 함

- 화면 읽기 프로그램(VoiceOver 등) 전 구간 읽기: VoiceOver 구현·검증 제외가 설계 전제라,
  실제 수업 전에 선생님과 함께 한 번 읽어봐야 한다.
- 학생 1~2명과 25분 전체 흐름 점검: 예측 문장이 막히는지, 한 단계 버튼을 찾는지 본다.
