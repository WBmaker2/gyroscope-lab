# 성능 기록 (공통 원칙 §6-4)

측정일: 2026-09-23. 대상 기기: MacBook + 헤드리스 Chrome (로컬 미리보기).
교실 크롬북은 더 느릴 수 있으나, 계산 자체가 가벼워 여유가 크다.

## 전송 크기 (빌드 결과)

- 첫 로딩: JS 28KB + CSS 7KB + HTML 15KB (gzip 합계 약 18KB).
- three.js 527KB(gzip 132KB)는 3D 버튼을 처음 누를 때만 내려받는다.
  2D만 쓰면 받지 않는다.

## 시간

| 항목 | 실측 | 목표 |
|---|---|---|
| 초기 표시 (DOMContentLoaded) | 15ms (로컬) | — |
| 한 단계 (계산+그림+표) | 61.7ms | 100ms 이내 |
| 10초 시뮬레이션 계산 (20000 스텝) | 31.2ms (Node) | — |
| 스텝당 평균 | 1.7μs | — |

한 단계는 누를 때마다 전체(20000 스텝)를 다시 계산하고 화면용 진실값도
다시 적분한다. 그래도 100ms 안에 든다. 무거운 계산 취급(진행·취소 표시)이
필요한 수준이 아니라 1배속 재생으로 충분하다.

## 메모리

- JS 힙 사용 10MB (실행 직후, Chromium `performance.memory`).

## 회귀 검사

`tests/perf.test.ts`가 상한만 검사한다 (10초 실행 < 10초, 스텝당 < 1ms).
정확한 수치는 이 문서에 기록한다.
